# ATLAS · Global Sector Ontology

전 산업의 수요·공급 균형과 사이클 위치를 추적하는 살아있는 투자 리서치 지도.
데워지는 산업을 포착하고, 그 산업에서 지금 봐야 할 기업을 계층(대장·국면 주도주·고베타 유망주)으로
좁혀 하류 공정(스크리닝→딥다이브)으로 넘긴다.

> 티어·role은 **조사 우선순위**이며 매매 신호가 아니다.
> 기업 노드는 `verification` 값으로 진하기를 구분한다 — **SHALLOW**(미검증 후보 분류)와
> **DEEP_DIVED**(딥다이브로 해자·재무·경영진까지 검증됨). DEEP_DIVED 노드에 붙은 스탠스는
> **별도 공정(딥다이브)의 인용**이며 아틀라스가 내린 매매 의견이 아니다.

## 구조 — 데이터 하나, 뷰 넷

```
atlas_site/
  index.html            ← 콘솔로 자동 이동
  ATLAS_CONSOLE.html    ← 메인. 섹터 브라우저 + 필터 + 드릴다운
  ATLAS_GRAPH.html      ← 관계망 탐색 (엣지 따라 꼬리 물기)
  ATLAS_MAP.html        ← 히트맵 (인쇄·공유용)
  ATLAS_GUIDE.html      ← 사용 가이드

  00_ATLAS_OS.md                 ← 미션·상태파일 원칙·3개 모드·금지사항  ┐
  01_ATLAS_TAXONOMY_SCORING.md   ← 분류·산업카드·트리거·티어·PACK 스펙   │ 판단 로직
  02_ATLAS_BUILD_GOVERNANCE.md   ← BUILD 증분 구축 규율                  │
  03_ATLAS_UPDATE_GOVERNANCE.md  ← UPDATE 세션 규율                     ┘
  SOP.md                ← ★ 운영·배포 절차
  ATLAS_USAGE.md        ← 활용 가이드 (무엇을 어디까지 요청하나)

  data/
    ATLAS_PACK.json     ← ★ 지도의 원본 데이터 (유일한 원본)
    deepdive/           ← 개별 딥다이브 원본 아카이브 (사이트 미사용)
```

### 문서 지형 (역할 경계)

| 문서 | 관장 | 질문 |
|---|---|---|
| `00 / 01 / 02 / 03` | **판단 로직** (분류·채점·티어·전파·세션 규율) | "무엇을 어떻게 판단하나" |
| `SOP.md` | **운영·배포 절차** (트리거·산출물·깃허브·하드룰) | "어떻게 돌리고 반영하나" |
| `ATLAS_USAGE.md` | **활용 가이드** (요청 가능한 작업·경계) | "뭘 어디까지 물어보나" |

충돌 시: **판단 기준은 00/01/02/03이, 절차는 SOP가 관장**한다.

> **이 6종은 레포가 원본이고, 프로젝트 knowledge의 것은 사본이다.** 고칠 때는 양쪽을
> 같은 세션에서 함께 갱신하고 md5 일치를 확인한다(SOP 「문서 갱신 규칙」).
> knowledge에 상주 중이므로 프로젝트 안의 대화는 **최신 `data/ATLAS_PACK.json`만 첨부**하면 된다.
> 프로젝트 밖의 대화라면 그때만 `SOP.md`를 함께 첨부한다.

**콘솔·관계망·히트맵 세 뷰 모두 열릴 때 `data/ATLAS_PACK.json`을 읽어 그 자리에서 화면을 만든다.**
그래서 매달 갱신할 때 **이 파일 하나만 교체**하면 세 뷰가 동시에 새 데이터로 갱신된다.
(2026-08 히트맵도 fetch 기반으로 전환 완료 — 더 이상 히트맵을 따로 재생성할 필요가 없다.)

### 딥다이브 노드 가시성 (검증된 진한 노드)

bottom-up 딥다이브를 마친 기업은 `아틀라스 업데이트`로 통합되면 PACK의
`company_nodes`에서 `DEEP_DIVED`로 승격되고, 해당 산업의 밸류체인(⑦ companies)에 편입되며
`deep_dive_ref`(스탠스·한 줄 thesis·해자·경영진·KPI)를 갖는다. 두 메인 뷰는 이를 이렇게 드러낸다:

- **콘솔** — 산업 드릴다운에 role 계층(대장·국면 주도주·고베타) 아래로
  **「밸류체인 편입 기업 · 커버리지」** 블록을 두어, 역할 태그가 없는 기업도 전부 보여준다.
  딥다이브 완료 기업은 **✓ 검증** 배지 + 판정(스탠스·thesis)이 함께 뜨고, 섹터 그리드의
  해당 산업 카드에도 ✓ 표식이 붙는다.
- **관계망** — 딥다이브 기업은 역할이 없어도 노드로 나타나며 **청록 검증 링**으로 구분된다.
  노드를 클릭하면 인스펙터에 `deep_dive_ref` 전체(스탠스·thesis·해자·경영진·KPI tripwire)가 뜬다.

즉 "대장도 유망주도 아닌" 기업이라도 딥다이브만 하면 **제 밸류체인에 편입되어 확인 가능**하다.
role은 트리거 기준 조사 우선순위 태그일 뿐, 커버리지 편입과는 별개다.

> **뷰 업그레이드는 1회성이다.** 위 가시성 기능은 `ATLAS_CONSOLE.html`·`ATLAS_GRAPH.html`
> 코드에 들어 있다(2026-08 업그레이드). 두 파일을 한 번 교체한 뒤로는, 딥다이브가 늘어나도
> **매달 `data/ATLAS_PACK.json` 하나만 교체**하면 새 검증 노드가 자동으로 두 뷰에 반영된다.

## GitHub Pages로 올리기

아래 별도 안내(`GITHUB_안내`)를 따르면 된다. 요약:

1. GitHub에 새 저장소 생성
2. 이 폴더 전체를 업로드 (`index.html`, 4개 HTML, 지침 문서 6종, `data/` 폴더, `README.md`)
3. Settings → Pages → Source: `main` 브랜치 저장
4. `https://<아이디>.github.io/<저장소>/` 로 접속

`.md` 문서는 Pages가 렌더링만 하고 사이트 동작에는 관여하지 않는다 — 버전 관리용이다.

정적 사이트라 서버·빌드가 필요 없다.

### 로컬에서 미리 볼 때
콘솔·관계망은 데이터를 `fetch` 로 읽으므로, `file://` 로 더블클릭하면 브라우저 보안 정책 때문에
데이터를 못 읽는다. 로컬 확인이 필요하면 폴더에서 아래를 실행하고 `localhost:8000` 으로 접속한다:
```bash
python3 -m http.server 8000
```
가이드(`ATLAS_GUIDE.html`)만 데이터를 안 읽으므로 `file://` 로도 바로 열린다.
콘솔·관계망·히트맵은 fetch를 쓰므로 로컬 서버가 필요하다. GitHub Pages(https)에선 전부 정상 작동한다.

## 월간 갱신 워크플로우

1. 최신 `ATLAS_PACK.json`을 첨부하고 `아틀라스 업데이트` 트리거
2. 변화 신호가 있는 산업만 심층 확인 → 새 `ATLAS_PACK.json` + diff 리포트 생성
3. 저장소의 **`data/ATLAS_PACK.json` 하나만** 새 파일로 교체
4. GitHub Pages가 자동 반영 → 콘솔·관계망이 새 데이터로 갱신

지도의 원본은 항상 `data/ATLAS_PACK.json`. 갱신은 직전 PACK 기반의 diff로만 이루어진다.
